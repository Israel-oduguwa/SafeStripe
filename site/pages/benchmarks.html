Reading the numbers

The workload matters
as much as the rate.

1

Ten deliveries for each event

Admission runs sequentially in a closed loop. Attempts per second count repeated store calls, not unique payments.

2

Drain a prepared backlog

Worker lanes run in one process. Admission-to-commit latency includes the deliberate backlog; it is not a real-time payment SLA.

3

Keep each repetition

Percentiles use nearest rank. The tables show p50, p95 and p99 for each run, without averaging percentiles across runs.

4

Assert committed state

Each run checks one effect, one outbox intent and one completed job per unique event. Duplicate effects and failed attempts remain visible.

Reproduce the workload

Run it on your own hardware.

Use a repository checkout. Save the output JSON with your configuration rather than comparing unrelated machines as a capacity forecast.

Local SQLite

No database server required. The legacy baseline shared one SQLite connection.

npm ci
npm run benchmark

Disposable PostgreSQL

Set a private CHAOS_DATABASE_URL for a disposable test database. The harness creates its own schema. 

BENCH_DATABASE=postgres \
BENCH_EVENTS=10000 \
BENCH_WORKERS=8 npm run benchmark

Not measured: database CPU and memory, transaction retries before the callback begins, process recovery time, multiple-host throughput or production network latency. Hosts differ across configurations. SQLite's laptop baseline is not comparable capacity evidence for PostgreSQL.
